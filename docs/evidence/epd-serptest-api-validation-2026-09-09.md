## Actual blockers and remaining implementation

Both CUA browser attempts (in-app and Chrome) refused the new hostname with
`net::ERR_BLOCKED_BY_CLIENT`; the page remained blank. HTTP API requests work. The legacy
Playwright MCP tab-list call timed out after 120 seconds. The dedicated Gateway browser session
still displays its Test Account banner. This does not establish a provider permission failure.

No actual card submission, approval, stored-vault renewal, decline or refund was tested in this
run. Follow-up diagnosis observed Chrome's rendered error page, `ERR_BLOCKED_BY_CLIENT`, and
the document's CDP `Network.loadingFailed` event with `blockedReason: inspector`. No HTTP
response from the checkout was received by that navigation. Browser console warnings/errors
were empty. This narrows the failure to browser-side tooling but does not identify the exact
rule or establish an EPD account problem.

The documented browser troubleshooting path was checked. Native access to the Codex app was
explicitly denied by Computer Use, so the agent could not inspect Settings > Browser site
permissions. No browser protections, request-blocking rules or access controls were disabled;
no alternate hostname/proxy was introduced to evade the block. A permitted browser session
that can load this exact staging hostname remains necessary for hosted Collect.js proof.

optional Query vault evidence with the matching initial-sale checkpoint. Missing, duplicate or
conflicting initial-sale vault evidence still stops before renewal. The report now identifies
